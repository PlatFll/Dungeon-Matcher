Assembly and review gates

Use text-driven PixelLab generation for each scoped group, followed by LibreSprite native cleanup and exact exports. Do not upload the target to reproduce it. Save every candidate, selected lineage, prompt, cost and palette. Do not generate characters, gems, buttons or health bars.

Keep distant bridge/path depth in the scenery and the actual combat platform side-on. Fit three enemies, their health bars and countdowns. Use one full-screen background under all layers; overfill masked panel interiors. Anchor one coherent formation at each lower corner and tile quiet join sections instead of stacking decorated strips.

The existing DungeonPresentationArt, BattleBackgroundTilemapController, ResponsiveModularFrameFitter and shared layout owners are the integration seams. Frostwake currently uses the legacy theme path; the shared control resource resolver does not yet include it. A later scoped adapter must opt into existing shared controls without changing other zones. Do not run the old broad Frostwake importer over approved characters or settings.

Before each later approval: inspect native pixels, binary alpha and canvas clearance; repeat joins in both axes; verify centered connectors and an overfilled portrait mask; capture actual Unity at 360×640, 720×1280, 1080×1920, 1080×2400 and notch/side/bottom safe areas. Compare board/portrait dimensions and feet/health positions across zones. Preserve the known uniformly fitted board scaling. Check full-screen coverage and input ownership. Animation must honor pause and Reduced Motion.

Historical layout captures are retained as context only: they already show equal board/portrait dimensions and enemy feet lines, with some legacy Snow HUD vertical offsets. No fresh Unity validation is claimed for this documentation-only stage. Take a fresh baseline before later visual integration.

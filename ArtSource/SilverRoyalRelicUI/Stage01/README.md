## Validation and limits

- Six PNGs: exact dimensions, 0/255 alpha, 11–13 opaque colors, at least 2 native
  transparent pixels around occupied content, no clipping.
- Reopened all six ASE files in LibreSprite and compared every visible RGB pixel
  and alpha value exactly with the intended edits. Hidden RGB beneath alpha=0 is
  ignored because PNG encoders can change that invisible payload.
- Inspected native art and integer enlargement. The broad A bevel and gear read
  most clearly; B is a lighter ornamental option; C's smaller gear is deliberate
  in this exploratory sheet and would need production sizing after selection.
- Verified production files against the starting 9164-file hash inventory.
  No game art, code, scenes, settings or packages were changed.
- No fresh Unity runtime/compilation or device validation was performed or claimed:
  Stage 1 contains no Unity assets or implementation changes.
- Browser surface swatches are contrast review aids, not actual cross-zone tests.

## Reproduction

Use the existing Foundry art Python and LibreSprite installation. `cleanup.py`
prepares explicit edits and executes them through `cleanup_body.js` inside
LibreSprite, then uses native batch crop/export and verifies the six outputs.
`build_review.py` produces only review layouts. `verify.py` rechecks preservation,
lineage and exports. `prepare.py` is the original baseline capture; **do not rerun
it on changed production files**, because it records the starting hashes.
The full per-pixel edit plan and generated JavaScript are retained locally and
regenerated by `cleanup.py`; these bulky derived files are excluded from Git.

The installed LibreSprite JS crop call returned unchanged dimensions during
verification; the final workflow uses its working native batch crop command.
Each cropped ASE is exported in a new invocation to avoid applying the crop twice.

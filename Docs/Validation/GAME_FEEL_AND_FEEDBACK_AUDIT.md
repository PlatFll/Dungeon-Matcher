# Dungeon Matcher game feel, sound and visual feedback audit

## Executive summary

The board already has a convincing impact. In the Game scene a matched gem breaks on the same frame that the sound and vibration requests arrive. A rejected swap comes back without spending a move. The mouse actually hums while browsing, responds to the item purchased, waves and disappears behind the counter. Keep those timings and performances. The biggest opportunity is the beat *after* a decision. Buying a potion changes two numbers, breaking a shield can save a life, and clearing a warned gem can cancel an attack. The game knows which result occurred. Too often the player has to reconstruct it.

The empty Build guide also tells players to wait until after wave 2. That directly contradicts the first 12-point Resonance notch and should be corrected before adding any new flourish.

Start with three things a first-time player should be able to say out loud: “I have time to think,” “that purchase went through,” and “I stopped that attack.” For a returning player, the same information should fit in a facet flash, a change of silhouette or a short sound. Reserve text and longer musical phrases for new information. Nothing proposed here needs to own an action, advance a turn, extend a lock or mint a reward.

## Interaction inventory and findings

Each row includes the player-facing trigger, evidence and classification, the proposed visual and sound with timing, the owner to observe, and a falsifiable check. Durations are design starting points. **Good** means good as-is. **Weak** means the result exists but is easy to miss. **Missing** refers to the specific receipt or distinction named in that row. **Incorrect** marks a mismatch between what a player can see and what the UI says or remembers. **Inconsistent** marks two paths that describe similar results differently. **Excessive** is used for a demonstrable overlapping path or identified exposure risk, with the test needed to distinguish it from actual sensory overload. P0 protects understanding, P1 improves frequent consequential actions, P2 adds character or context, and P3 is optional. Effort is relative to the existing presentation owners.

## Visual timing and motion guide

| Scale | Practical motion | Typical use and restraint |
|---|---|---|
| Contact | Immediate pressed silhouette, one native-pixel inset, release within 80–110 ms | All buttons. Move icon and label as one group. Keep hit target and text baseline stable. Cancel unconditionally when gesture is cancelled. |
| Routine result | 60–140 ms local rim flash, sprite contact, chip or small number | Per swap/hit/equip/stock change. Use the existing [CombatTextController] for effective damage, heals and shields. Add semantic accents to its single number instead of a second emitter. |
| Significant result | 140–240 ms grouped number transition and one local accent | Actual purchase, upgrade, special or counter. Derive deltas from committed before/after values, not label parsing. Repeated accepted actions should merge visual tails, never lose accounting. |
| Major event | One 180–350 ms musical/visual accent, followed by a stable readable objective | Boss, true unlock, banked milestone, destination or death. Interactive UI stays responsive. Do not add waits to the board or the card coordinator. |
| Persistent information | Static native icon, stable outline and readable word/number for as long as the decision exists | Imminent crumbling, frost stage, locked item, low AIR, capstone seal. Use shape and value as well as hue. Existing character poses, silhouettes, grounded feet and ability icon centres take precedence over particles. |

**First run and fiftieth run.** Teach the clock, first blocker counter, provisional Resonance and first item swap once when visible. Keep later reminders local and brief. In a crowded turn, prefer one target mark, one break and one danger cue to five overlapping text popups. Keep HUD feedback in its own safe inset, align optical centres inside frames, reserve margins for long strings and changing digits. At native scale verify both the effect and what lies behind it.

**Motion, audio and touch.** Reduced Motion substitutes a steady edge, silhouette or short crossfade for travel, shake and particle streaks. Essential state survives with SFX, music and vibration all off. Apply haptics only through the existing preference and strongest-event gate. Pause stops combat cadences and one-shots, menu navigation stays responsive, and resume reconstructs steady state silently. Recycle short-lived UI and effects. Profile the busiest board on a slower phone at 30 Hz and check a second pass at 60 Hz, speaker mono and headphones. Peak/thermal cost, physical vibration, audibility on a handset and long-session fatigue remain unverified.
